    4. Widgets

    Writing your own widgets is at the heart of working with [Flutter]: a well-written screen is made up of small widgets, each with its own parameters, its [build], and, if necessary, its state. This chapter shows how they communicate with each other (parameters, functions), how they are assembled (composition), how they function (lifecycle), how they share data without passing it from one to another (inherited data), and how to reuse behavior.

    // =========================================================================
// lib/ex10_widgets_parametres/carte_medecin.dart - a widget ENFANT
// -------------------------------------------------------------------------
// It receives its data from its parent via the PARAMÈTRES fields of its
// constructor, stored in final fields. Their type is verified during
// compilation stage: CarteMedecin (doctor: 42) would be rejected.
//    - required: the parent DOIT must provide this parameter;
//    - this.compact = false: an optional parameter with its default value.
//
// Golden rule: a widget does not inherit its parameters (they are final).
// Data flows from the parent to the child; to request a
// change, the child calls a function passed to it by the parent
// (see Example 11). When the parent changes its data, it RECONSTRUIT its
// children with new parameters.
// =========================================================================

import 'package:flutter/material.dart';

import 'medecin.dart';

// the map’s “style”: constants PRIVÉES in this file (the “_”).
// No other widgets can see them or be affected by them
const _couleurInitiales = Color(0xFF087EA4);
const _styleInitiales = TextStyle(color: Colors.white, fontWeight: FontWeight.bold);

class CarteMedecin extends StatelessWidget {
  final Medecin medecin;
  final int rang;
  final bool compact;

   // const: if all parameters are constant, the widget is also constant
   // (Flutter doesn’t even need to rebuild it)
  const CarteMedecin({super.key, required this.medecin, required this.rang, this.compact = false});

  @override
  Widget build(BuildContext context) {
     // a value calculated from the parameters
    final initiales = '${medecin.prenom[0]}${medecin.nom[0]}';

    return Card(
       // a green border for an available doctor
      shape: RoundedRectangleBorder(
        borderRadius: BorderRadius.circular(12),
        side: medecin.disponible ? const BorderSide(color: Colors.green, width: 2) : BorderSide.none,
      ),
      child: Padding(
        padding: const EdgeInsets.all(12),
        child: Row(
          children: [
            CircleAvatar(
              backgroundColor: _couleurInitiales,
              child: Text(initiales, style: _styleInitiales),
            ),
            const SizedBox(width: 12),
             // Expanded: the text takes up the entire remaining width
            Expanded(
              child: Column(
                crossAxisAlignment: CrossAxisAlignment.start,
                children: [
                  Text(
                     '$rang. ${medecin.titre} ${medecin.prenom} ${medecin.nom}',
                    style: Theme.of(context).textTheme.titleMedium,
                  ),
                  if (!compact) Text(medecin.specialite, style: const TextStyle(color: Colors.grey)),
                ],
              ),
            ),
          ],
        ),
      ),
    );
  }
}
    • lines 23–24: the map’s “style”: constants private to this file (the underlined ones). No other file can see them or be affected by them. This is the equivalent, in [Flutter], of the “CSS modules” in [React]: there is no global stylesheet; a widget’s style is embedded in its code;
    • lines 27–29: the widget’s parameters, stored in [final] fields;
    • line 33: the constructor. [required this.medecin]: a required parameter, stored directly in the field; [this.compact = false]: an optional parameter, with its default value. The constructor is [const]: if all arguments are constant, the map is also constant;
    • line 38: a value calculated from the parameters;
    • lines 42–44: the card’s shape ([Card]): rounded corners and a green border if a doctor is available ([BorderSide.none] otherwise);
    • lines 50–52: a colored disc with the initials;
    • line 64: the specialty is only displayed in non-compact view.

    Golden rule: a widget never modifies its own parameters (they are [final]; the compiler prohibits this, by the way). Data flows from the parent to the child; to request a change, the child calls a function passed to it by the parent (Example 11). When the parent changes its data, it reconstructs its children with new parameters.

    // =========================================================================
// lib/ex11_remonter_l_information/compteur.dart
// -------------------------------------------------------------------------
// A child who PRÉVIENT their parent: the parent passes them FONCTIONS in
// parameters (by convention, their names begin with "on"), and the child
// calls them when something happens:
//      Counter(label: 'Coffees', max: 3, onIncremente: ..., onLimite: ...)
// These function types have predefined names in Flutter:
//    - ValueChanged<int>: a function that takes an int and returns nothing;
//    - VoidCallbac     k : a function with no parameters that returns nothing.
// =========================================================================

import 'package:flutter/material.dart';

class Compteur extends StatefulWidget {
  final String libelle;
  final int max;
  final ValueChanged<int> onIncremente; // with the new value
  final VoidCallback onLimite; // with no data

  const Compteur({
    super.key,
    required this.libelle,
    required this.max,
    required this.onIncremente,
    required this.onLimite,
  });

  @override
  State<Compteur> createState() => _CompteurState();
}

class _CompteurState extends State<Compteur> {
   // the state PROPRE for this counter: each counter has its own
  int _valeur = 0;

  void _plus() {
     // widget: within the State object, provides access to the widget’s parameters
    if (_valeur >= widget.max) {
      widget.onLimite();
      return;
    }
    setState(() => _valeur++);
     // on the parent PRÉVIENT, passing the new value to it
    widget.onIncremente(_valeur);
  }

  @override
  Widget build(BuildContext context) {
    return Row(
      children: [
        SizedBox(width: 110, child: Text(widget.libelle)),
        OutlinedButton(onPressed: _plus, child: const Text('+1')),
        const SizedBox(width: 12),
        Chip(label: Text('$_valeur / ${widget.max}')),
      ],
    );
  }
}
    • lines 18–19: two parameters that are functions, which the counter will call. [ValueChanged<int>] is the type of a function that takes a [int] and returns nothing; [VoidCallback] is the type of a function with no parameters. By convention, their names begin with “on,” such as [onPressed] or [onChanged] for the widgets of [Flutter];
    • line 35: the state PROPRE for this counter: each [Compteur] has its own;
    • lines 37–45: within the [State] object, [widget] provides access to the widget’s settings: [widget.max], [widget.onLimite]... If the maximum is exceeded, the counter notifies its parent ([widget.onLimite()]); otherwise, it changes its state and then notifies its parent by transmitting the new value. Unlike [React], the state is updated immediately: [_valeur] already has its new value when it is transmitted.

// lib/ex11_remonter_l_information/champ_texte.dart - a widget CONTRÔLÉ
// -------------------------------------------------------------------------
// A "custom" form field (label + field + tooltip + character counter
// ) that is used as a controlled field:
//      ChampTexte(value: _nom, onChanged: (v) => setState(() => _nom = v), ...)
// The value belongs to PARENT, which passes it (the value) to it and which
// notifies of every keystroke (onChanged). The parent decides.
//
// A challenge specific to Flutter: a TextField stores its text in a
// controller, which must survive rebuilds. The widget therefore has a
// state (the controller)... which it must maintain at JOUR when the parent changes
// its value (the “Clear” button): this is the role of didUpdateWidget.
// =========================================================================

import 'package:flutter/material.dart';

class ChampTexte extends StatefulWidget {
  final String valeur;
  final ValueChanged<String> onChanged;
  final String libelle;
  final int max;
  final String aide;

  const ChampTexte({
    super.key,
    required this.valeur,
    required this.onChanged,
    required this.libelle,
    required this.max,
    this.aide = '',
  });

  @override
  State<ChampTexte> createState() => _ChampTexteState();
}

class _ChampTexteState extends State<ChampTexte> {
   // late: the field will be initialized later (in initState), before it is used
  late final TextEditingController _controleur;

  @override
  void initState() {
    super.initState();
    _controleur = TextEditingController(text: widget.valeur);
  }

   // called when PARENT rebuilds this widget with new parameters;
   // old: the previous widget, for comparison
  @override
  void didUpdateWidget(ChampTexte ancien) {
    super.didUpdateWidget(ancien);
    if (widget.valeur != _controleur.text) {
      _controleur.text = widget.valeur; // the parent changed the value itself
    }
  }

  @override
  void dispose() {
    _controleur.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    final plein = widget.valeur.length == widget.max;
    return TextField(
      controller: _controleur,
      maxLength: widget.max, // the field rejects excess characters
      decoration: InputDecoration(
        labelText: widget.libelle,
        helperText: widget.aide,
         // the border turns red when the field is full
        errorText: plein ? 'Longueur maximale atteinte' : null,
      ),
      onChanged: widget.onChanged, // the parent's function, passed as-is
    );
  }
}

    A “custom” form field (label + field + tooltip + character counter) that functions as a controlled field: the value belongs to the parent, which passes it to the field ([valeur]) and notifies the parent of each keystroke ([onChanged]).

    • Line 40: [late]: This field will be initialized later (in [initState]), but before it is used. [Dart] checks it at runtime;
    • Lines 43–45: The controller starts with the parent’s value;
    • lines 51–54: This is the specific challenge with [Flutter]: a [TextField] stores its text in a controller, which must survive page rebuilds. The widget therefore has a state (the controller)... which it must keep up to date when the parent changes the value itself (Clear button). [didUpdateWidget] is called every time the parent rebuilds this widget with new parameters; it receives the old widget for comparison. If the parent’s value differs from the field’s text, it is copied over;
    • line 69: the field rejects excess characters and displays a counter (“12/20”);
    • line 72: a tooltip appears below the field;
    • line 74: the border turns red when the field is full;
    • line 76: the parent’s function, passed as-is to [TextField].

    if (ancien.couleur != widget.couleur) {
      _journaliser('Horloge : didUpdateWidget - nouvelle couleur');
    }
  }

  @override
  void dispose() {
    _minuterie.cancel(); // NETTOYAGE
    _journaliser('Horloge : dispose - minuterie arrêtée');
    super.dispose(); // always last
  }

  @override
  Widget build(BuildContext context) {

      _heure,
      style: TextStyle(fontSize: 40, fontFamily: 'RobotoMono', color: widget.couleur),

// lib/ex16_confirmation/confirmation.dart - “Are you sure?”
// -------------------------------------------------------------------------
// Flutter provides everything you need: showDialog() displays a window
// MODALE on top of the screen and returns a Future, resolved with the value
// which the window transmits when it closes: Navigator.pop(context, value).
// The calling code is therefore very simple:
//
//      if (await confirm(context, 'Delete this doctor?')) { ... }
//
// Closing the window SANS (by tapping outside the window, pressing the Back button on the
// phone, or the Esc key) resolves the Future to null: we treat it
// as a "no".
// =========================================================================

import 'package:flutter/material.dart';

Future<bool> confirmer(BuildContext context, String message) async {
  final reponse = await showDialog<bool>(
    context: context,
     // AlertDialog: a Material window, with a title, content, and buttons
    builder: (context) => AlertDialog(
      title: const Text('Confirmation'),
      content: Text(message),
      actions: [
         // autofocus: the "No" button (the least risky choice) has focus
        TextButton(autofocus: true, onPressed: () => Navigator.pop(context, false), child: const Text('Non, revenir')),
        FilledButton(
          style: FilledButton.styleFrom(backgroundColor: Colors.red),
          onPressed: () => Navigator.pop(context, true),
          child: const Text('Oui, confirmer'),
        ),
      ],
    ),
  );
  return reponse ?? false; // null: window closed without a response
}

          }),
        ),
      ),
    );
