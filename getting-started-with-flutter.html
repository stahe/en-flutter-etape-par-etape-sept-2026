    3.1. Example 01: The Structure of a Flutter Application

    3.1.1. The Project

    A [Flutter] project is created using the [flutter create] command:

    1
    flutter create --org fr.stahe --platforms=android,web,windows mon_application
    • [--org fr.stahe]: the prefix of the app ID, reversed like a domain name. The app [Android] will be named [fr.stahe.mon_application]; two apps installed on the same phone must have different IDs;
    • [--platforms=...]: the target platforms. For each one, [flutter create] creates a folder ([android/], [web/], [windows/], and also [ios/], [macos/], [linux/] if requested): a small, platform-specific project that simply launches the [Flutter] engine and loads the application into it. We rarely make changes to it (the application’s name, icon, and permissions);
    • [mon_application]: the project name, which is also the package name [Dart]: lowercase letters, numbers, and underscores.

    The command generates a complete, ready-to-run application (a counter). The example project was created in the same way, and then its [lib/] folder was filled in manually to combine twenty-five applications into a single project: this way, they share the same packages, which are downloaded only once.

To add a package, rather than editing the file manually, you can type [flutter pub add go_router]: the command adds the line with the latest version of the package.

// Everything in a Flutter app is a WIDGET: an object that describes
// a part of the screen (text, a button, a margin, a column...).
// Widgets nest inside one another and form a ARBRE.
// A widget has a build() method, which RENVOIE assembles the widgets that
// compose it. Flutter calls `build()` to render the screen; it
// RAPPELLE every time the widget’s state changes (setState), and updates
// the screen with the new result.
// =========================================================================

import 'package:flutter/material.dart';

// "Regular" data, outside of widgets: it never changes
const titre = 'Bienvenue dans Flutter';
const langages = ['Dart', 'Flutter', 'Material Design'];

// "12:05:09": the current time, displayed as two digits
String heureCourante() {
  final d = DateTime.now();
  String deuxChiffres(int n) => n.toString().padLeft(2, '0');
  return '${deuxChiffres(d.hour)}:${deuxChiffres(d.minute)}:${deuxChiffres(d.second)}';
}

// the entry point of any Dart program
void main() {
   // runApp: Flutter takes control of the screen and displays the RACINE widget
  runApp(const Application());
}

// the root widget: it configures the app (title, theme, first screen).
// StatelessWidget: a SANS state widget, fully described by its parameters
class Application extends StatelessWidget {
  const Application({super.key});

  @override
  Widget build(BuildContext context) {
     // MaterialApp: an app with the colors and behavior of
     // Material Design, Google’s visual language
    return MaterialApp(
      title: 'Exemple 01',
       // no "DEBUG" banner in the corner of the screen
      debugShowCheckedModeBanner: false,
       // the colors of the entire app, derived from a base color
      theme: ThemeData(colorSchemeSeed: Colors.indigo),
      home: const PageAccueil(),
    );
  }
}

// A AVEC state widget: it consists of two parts—the widget itself (which
// ever changes) and a State object (which contains the data that changes)
class PageAccueil extends StatefulWidget {
  const PageAccueil({super.key});

  @override
  State<PageAccueil> createState() => _PageAccueilState();
}

// the "_": this class is PRIVÉE, invisible outside this file
class _PageAccueilState extends State<PageAccueil> {
   // ÉTAT: simple fields of the State object
  int _compteur = 0;
  String _heure = heureCourante();

   // the function called by the button
  void _incrementer() {
     // setState: the state is modified DANS the function passed to setState;
     // Flutter then calls build() to update the screen. We

    • Line 13: the [Material] library from [Flutter]: all the widgets from [Material Design], the visual language of [Google] (buttons, input fields, bars, windows, etc.). It imports the rest of [Flutter] itself;
    • lines 16–17: two ordinary data values, declared outside the widgets: they never change. [const]: a constant known at compile time;
    • lines 20–23: an ordinary function that returns the current time in the format “12:05:09.” It contains a small function of its own, [deuxChiffres], written on a single line with [=>];
    • lines 27–29: the function [main], called at launch. [runApp] starts [Flutter]: it takes control of the screen and displays the widget provided to it—the root of the application.

    The root widget, [Application]:

    • Line 34: A widget is a class. This class inherits from [StatelessWidget], a stateless widget: what it displays depends solely on its parameters and never changes on its own;
    • Line 29: its constructor. [{super.key}]: an optional named parameter passed to the parent class. Every widget has one: the “key” that identifies it (see Example 04). The constructor is [const]: [Application()] can be a constant that [Flutter] never needs to reconstruct;
    • Lines 38–47: the [build] method, the core of a widget. It returns the widgets that make it up. [@override]: it overrides the [build] method of the parent class. The parameter [context] is the widget’s position in the widget tree: it is used to retrieve what its ancestors provide (the theme, for example, line 90);

    The first screen, [PageAccueil], has data that changes: it is a stateful widget.

    • Lines 54–58: A [StatefulWidget] consists of two parts. The widget itself, like any widget, never changes (its fields would be [final]); its sole task is to create, via [createState], a [State] object, which in turn contains the data that changes. [Flutter] creates this object once and retains it as long as the widget remains in the same place in the tree;
    • line 62: the object [State]. Its name begins with an underscore: in [Dart], everything beginning with [_] is private and invisible outside the file;

    • lines 79–105: the [build] for the screen:

      • [AppBar]: the top bar; its title is a widget ([Text]), as is almost everything in [Flutter];
      • [Padding]: a margin around its single child, [child]. [EdgeInsets.all(16)]: 16 points on each side (a logical “point,” independent of screen density: approximately 2.6 pixels on the phone shown in the screenshots);
      • [Column]: its children, [children], arranged one below the other. [crossAxisAlignment: CrossAxisAlignment.start]: left-aligned (the “transverse” axis of a column is the horizontal axis);
      • [Text]: text. Its style may be derived from the theme: [Theme.of(context).textTheme.headlineSmall] is the style for “small headings”;
      • [SizedBox]: an empty box with a specified height—a space between two widgets;
      • line 98: [${expression}] inserts the value of an expression into a string; [$nom] is sufficient for a simple variable (line 104);
      • line 101: a button. [onPressed] takes the function to be called when the button is pressed. We specify the function itself, without parentheses: [onPressed: _incrementer()] would call it immediately, during screen construction;
      • lines 104–105: text that depends on the state. When the state changes, [build] is called, and this text changes.

    Two notes regarding [Dart]:

    • almost all widget arguments are named parameters ([title: ...], [child: ...]): the widget tree reads like a description, and the order of the arguments does not matter. A named parameter is optional, unless it is declared as [required];
    • the keyword [const] preceding a widget ([const SizedBox(height: 12)]) creates it once and for all at compile time. [Flutter] then knows that it never changes and doesn’t waste time comparing it. The parser flags any [const] that have been omitted; [VS Code] knows how to add them on its own.

// The widget no longer modifies the state: it DÉCRIT what happened, via a
// object ActionProfil (Edit(Champ.nom, 'Dupont'), Exit(Champ.nom)...), and

// possible actions, and a switch statement on an action is checked by the compiler
// (a missed case is an error).

class Profil {

// the reducer: it never MODIFIE uses the received state; it returns a new one.
// The switch “unpacks” each action: Modify(:final field, ...) reads
// its fields into variables of the same name
Etat reducteur(Etat etat, ActionProfil action) => switch (action) {
  Modifier(:final champ, :final valeur) => Etat(etat.valeurs.avec(champ, valeur), etat.touches),

  Majuscules() => Etat(
    etat.valeurs.copyWith(prenom: etat.valeurs.prenom.toUpperCase(), nom: etat.valeurs.nom.toUpperCase()),
    etat.touches,
  ),
  Reinitialiser() => const Etat(depart, {}),
};
