    5. Routing

    An application has multiple screens. [Flutter] manages them using [Navigator]: a stack of screens, where a new screen ([Navigator.push]) is pushed onto the stack and from which it is popped ([Navigator.pop], or the phone’s Back button). This is sufficient for a small mobile app. But as soon as you want URLs (/doctors/2)—that is, screens that can be referenced, opened from a link, reloaded on the web, and protected by guards—you use a router. The [go_router] package, maintained by the [Flutter] team and recommended in its documentation, is the most widely used.

    // =========================================================================
// lib/ex17_routeur/routes.dart - the application's ROUTES files
// -------------------------------------------------------------------------
// An application has multiple screens ("pages"). The ROUTEUR associates a
// ADRESSE (a path, like on the web: /doctors/2) to a screen. Flutter
// provides the Navigator (a PILE of screens: you stack them, you unstack them); the
// go_router package, maintained by the Flutter team, adds the
// addresses: links, parameters, the browser’s Back button
// and URLs typed manually on the web, the Android Back button.
//    '/doctors/:id'  :id is a parameter (/doctors/2 -> id = "2");
//    ShellRout      e a common “shell” (top bar, bottom
//                     bottom navigation bar) surrounding the route screens;
//    redirec        t a redirect: the old address leads to the new one;
//    errorBuilde    r the screen for an address that does not correspond to any route.
// =========================================================================

import 'package:go_router/go_router.dart';

import 'coquille.dart';
import 'pages/accueil.dart';
// loading DIFFÉRÉ: on the web, the code for this page is downloaded
// until the first visit (Flutter Build Web creates a separate file for it)
import 'pages/a_propos.dart' deferred as a_propos;
import 'pages/chargement_differe.dart';
import 'pages/detail_medecin.dart';
import 'pages/liste_medecins.dart';
import 'pages/page_introuvable.dart';
import 'pages/recherche.dart';

final routeur = GoRouter(
   // the starting address (on a phone: there is no address bar)
  initialLocation: '/',
  routes: [
    ShellRoute(
       // child: the screen for the current child route, placed DANS in the shell
      builder: (context, state, child) => Coquille(child: child),
      routes: [
        GoRoute(path: '/', builder: (context, state) => const Accueil()),
        GoRoute(
          path: '/medecins',
          builder: (context, state) => const ListeMedecins(),
           // a route IMBRIQUÉE: /doctors/2
          routes: [
            GoRoute(
              path: ':id',
               // pathParameters: path parameters, always CHAÎNES
              builder: (context, state) => DetailMedecin(id: state.pathParameters['id']!),
            ),
          ],
        ),
        GoRoute(
          path: '/recherche',
           // uri.queryParameters: parameters after the “?” (/search?q=pediatrician)
          builder: (context, state) => Recherche(q: state.uri.queryParameters['q'] ?? ''),
        ),
        GoRoute(
          path: '/a-propos',
          builder: (context, state) =>
              ChargementDiffere(charger: a_propos.loadLibrary, construire: () => a_propos.APropos()),
        ),
         // a redirect: the URL has no page; it returns another address
        GoRoute(path: '/docteurs', redirect: (context, state) => '/medecins'),
      ],
    ),
  ],
  errorBuilder: (context, state) => PageIntrouvable(adresse: state.uri.toString()),
);

    A route associates a path with a screen.

    • Line 23: a deferred import ([deferred]). On the web, this page’s code is compiled into a separate file, which is downloaded only on the first visit to the page ([a_propos.loadLibrary()]). On a phone, all the code is already in the app: [loadLibrary()] terminates immediately;
    • lines 30–32: the router, an object named [GoRouter], is created once, outside of any widget. [initialLocation]: the starting address (on a phone, there is no address bar to display it);
    • lines 34–36: a [ShellRoute] is a common container for several screens: the top bar and the bottom navigation bar. Its [builder] receives [child]—the current route screen—and places it within the shell. This is equivalent to nested routes and the [<Outlet />] of [React Router];
    • line 38: a route—its path—and a function that generates its screen. [state] ([GoRouterState]) describes the current navigation: the address and its parameters;
    • lines 40–47: the list of doctors, and a nested route: [':id'] under ['/medecins'] provides the path [/medecins/:id], where [:id] is a parameter ([/medecins/2]: [id] equals ["2"]). [state.pathParameters] provides the path parameters, which are always strings;
    • lines 52–54: [state.uri] is the full address; [queryParameters] contains the parameters following [?] ([/recherche?q=pédiatre]);
    • lines 57–59: the page loaded on demand by the [ChargementDiffere] widget (discussed later);
    • line 62: a redirect—the route has no screen; its function [redirect] returns another address, to which navigation is redirected;
    • line 66: the screen for an address that does not correspond to any route.

    // =========================================================================
// lib/ex17_routeur/coquille.dart - the application’s “shell”
// -------------------------------------------------------------------------
// The top bar, the bottom navigation bar, and, between them,
// the current route screen (child).
//    - GoRouterState.of(context).uri: the current URL;
//    - context.go('/doctors')       : go to an address. The stack of
//      screens is REMPLACÉE, replaced by that of this address (a tab);
//    - context.push('/doctors/2')   : EMPILER one screen above
//      the current screen; the Back button (or context.pop()) collapses it.
// =========================================================================

import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

// the tabs: (path, label, icon)
const onglets = [
  ('/', 'Accueil', Icons.home),
  ('/medecins', 'Médecins', Icons.people),
  ('/recherche?q=généraliste', 'Recherche', Icons.search),
  ('/a-propos', 'À propos', Icons.info),
];

class Coquille extends StatelessWidget {
  final Widget child;

  const Coquille({super.key, required this.child});

  @override
  Widget build(BuildContext context) {
    final adresse = GoRouterState.of(context).uri;
     // the active tab: the one whose path is the beginning of the current address
    int actif = 0;
    for (final (i, (chemin, _, _)) in onglets.indexed) {
      final debut = Uri.parse(chemin).path;
      if (debut != '/' && adresse.path.startsWith(debut)) actif = i;
    }

    return Scaffold(
      appBar: AppBar(title: const Text('Exemple 17 - le routeur')),
      body: Column(
        crossAxisAlignment: CrossAxisAlignment.stretch,
        children: [
          Container(
            color: Colors.grey.shade100,
            padding: const EdgeInsets.all(8),
             // Uri.decodeFull: %C3%A9 becomes active again
            child: Text(
              'adresse courante : ${Uri.decodeFull(adresse.toString())}',
              style: const TextStyle(fontFamily: 'RobotoMono', fontSize: 12),
            ),
          ),
          Expanded(
            child: Padding(padding: const EdgeInsets.all(16), child: child),
          ),
        ],
      ),
       // NavigationBar: the bottom tab bar, typical of a mobile device
      bottomNavigationBar: NavigationBar(
        selectedIndex: actif,
        onDestinationSelected: (i) => context.go(onglets[i].$1),
        destinations: [
          for (final (_, libelle, icone) in onglets) NavigationDestination(icon: Icon(icone), label: libelle),
        ],
      ),
    );
  }
}
    • Lines 17–21: the tabs: records (path, label, icon);
    • line 31: the current address. [GoRouterState.of(context)] is a legacy data read (see Example 14): the shell is reconstructed with each navigation;
    • lines 33–36: the active tab: the one whose path is the beginning of the current address. [for (final (i, (chemin, _, _)) in onglets.indexed)] parses both the (rank, tab) pair and the tab record, retaining only the path ([_]: “ignored”);
    • lines 48–49: the current address, displayed ([Uri.decodeFull]: [%C3%A9] reverts to [é]);
    • lines 53–54: the current route screen;
    • lines 59–63: the bottom tab bar ([NavigationBar]), typical of a mobile app. [onDestinationSelected] receives the index of the tapped tab; [context.go(chemin)] leads to its address. [onglets[i].$1]: the first field of a positional record.

    Two ways to navigate, using [go_router]:

    • [context.go('/medecins')]: Go to an address. The screen stack is replaced by the one described by this address. This is what you do to switch tabs;
    • [context.push('/medecins/2')]: Push the screen at this address onto the top of the current screen. The phone’s Back button (or [context.pop()]) pops it off the stack, and you return to where you were. This is how you “enter” a detail view.

    // =========================================================================
// lib/ex17_routeur/pages/detail_medecin.dart - a page with a parameter
// -------------------------------------------------------------------------
// The router passes it the :id parameter from the path, a CHAÎNE ("2").
// context.pop() navigates back a screen (like the Back button); context.go()
// leads to a different address. If you navigate from /doctors/1 to /doctors/2,
// Flutter reuses the same screen, simply rebuilt with a different ID.
// =========================================================================

import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

import '../donnees.dart';

class DetailMedecin extends StatelessWidget {
  final String id;

  const DetailMedecin({super.key, required this.id});

  @override
  Widget build(BuildContext context) {
     // int.tryParse: null if id is not a number; firstWhere... orElse: not found
    final numero = int.tryParse(id);
    final trouves = medecins.where((m) => m.id == numero);
    if (trouves.isEmpty) {
      return Text("Le médecin n° $id n'existe pas.", style: const TextStyle(color: Colors.red));
    }
    final medecin = trouves.first;
    final suivant = medecin.id % medecins.length + 1;
    return Title(
      title: '${medecin.prenom} ${medecin.nom}',
      color: Colors.indigo,
      child: Column(
        crossAxisAlignment: CrossAxisAlignment.start,
        children: [
          Text('${medecin.titre} ${medecin.prenom} ${medecin.nom}', style: Theme.of(context).textTheme.titleLarge),
          Text('Spécialité : ${medecin.specialite}'),
          const SizedBox(height: 16),
          Wrap(
            spacing: 8,
            children: [
              OutlinedButton(
                 // canPop: Is there a screen below this? (Not if you arrived
                 // directly at this address on the web)
                onPressed: () => context.canPop() ? context.pop() : context.go('/medecins'),
                child: const Text('Retour'),
              ),
              FilledButton(
                 // pushReplacement: replaces the current screen (no stacking)
                onPressed: () => context.pushReplacement('/medecins/$suivant'),
                child: const Text('Médecin suivant'),
              ),
            ],
          ),
        ],
      ),
    );
  }
}
    • line 16: the path parameter [:id], which the router passes to the manufacturer;
    • lines 23–26: [int.tryParse]: the numeric ID, or [null]; if a doctor cannot be found, a message is displayed;
    • line 45: Back: the screen is popped off the stack if there is one below it ([canPop]); otherwise (if you arrived directly at this address via the web), you go to the list;
    • line 50: the next doctor replaces the current screen (no stacking: the Back button returns to the list, not to the previous doctor).

// lib/ex17_routeur/pages/recherche.dart - a page driven by the URL
// -------------------------------------------------------------------------
// /search?q=pediatrician: the page is fully described by its URL.
// On the web, you can bookmark it, reload it, or go back to
// back. Searching is done at the address ALLER /search?q=<input>:
// The page displays what the URL says, and nothing else.
// =========================================================================

import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

import '../donnees.dart';

class Recherche extends StatelessWidget {
  final String q;

  const Recherche({super.key, required this.q});

  void _rechercher(BuildContext context, String saisie) {
     // URI: constructs the URL by encoding the necessary parts (é -> %C3%A9)
    context.go(Uri(path: '/recherche', queryParameters: {'q': saisie.trim()}).toString());
  }

  @override
  Widget build(BuildContext context) {
    final resultats = medecins
        .where((m) => '${m.prenom} ${m.nom} ${m.specialite}'.toLowerCase().contains(q.toLowerCase()))
        .toList();
    return Title(
      title: 'Recherche',
      color: Colors.indigo,
      child: ListView(
        children: [
           // a controlled NON field, which starts with the value of the URL;
           // key: ValueKey(q): if the address changes (Back button), Flutter
           // recreates the field, which then takes on the new value
          TextFormField(
            key: ValueKey(q),
            initialValue: q,
            decoration: const InputDecoration(hintText: 'nom ou spécialité', suffixIcon: Icon(Icons.search)),
            textInputAction: TextInputAction.search,
            onFieldSubmitted: (saisie) => _rechercher(context, saisie),
          ),
          const SizedBox(height: 8),
          for (final m in resultats) ListTile(title: Text('${m.prenom} ${m.nom} (${m.specialite})')),
          if (resultats.isEmpty)
            const ListTile(
              title: Text('Aucun résultat.', style: TextStyle(color: Colors.grey)),
            ),
        ],
      ),
    );
  }
}
    • Lines 20–22: Search for ALLER at the address [/recherche?q=<saisie>]. [Uri] generates the address by encoding the necessary information ([é] becomes [%C3%A9]). The page is fully described by its address: on the web, you can bookmark it, reload it, or go back;
    • lines 38–43: an unvalidated field that starts with the value of the URL. [key: ValueKey(q)]: if the URL changes (browser’s Back button), the key changes; [Flutter] recreates the field, which takes on the new value. [textInputAction: TextInputAction.search]: The Enter key on the phone’s keyboard acts as a magnifying glass.

// lib/ex17_routeur/pages/chargement_differe.dart
// -------------------------------------------------------------------------
// A screen whose code is loaded on demand (deferred import):
// load() downloads the code (a Future), build() constructs the screen
// once the code arrives. In the meantime: a loading indicator.
// FutureBuilder rebuilds its content when the Future completes
// (see Example 19).
// =========================================================================

import 'package:flutter/material.dart';

class ChargementDiffere extends StatefulWidget {
  final Future<void> Function() charger;
  final Widget Function() construire;

  const ChargementDiffere({super.key, required this.charger, required this.construire});

  @override
  State<ChargementDiffere> createState() => _ChargementDiffereState();
}

class _ChargementDiffereState extends State<ChargementDiffere> {
   // The Future is created UNE times (not with every build)
  late final Future<void> _chargement = widget.charger();

  @override
  Widget build(BuildContext context) {
    return FutureBuilder(
      future: _chargement,
      builder: (context, etat) => etat.connectionState == ConnectionState.done
          ? widget.construire()
          : const Center(child: CircularProgressIndicator()),
    );
  }
}
    • line 25: the code is loaded, initiated UNE times (a [late] field initialized on its first read): if it were initiated in [build], each reconstruction would trigger it again;
    • Lines 29–33: [FutureBuilder] rebuilds its content when [Future] terminates: in the meantime, a loading indicator; then, the screen (see Example 19).

import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

class PageIntrouvable extends StatelessWidget {
  final String adresse;

  const PageIntrouvable({super.key, required this.adresse});

  @override
  Widget build(BuildContext context) {
    return Title(

// -------------------------------------------------------------------------
// The logged-in user must be recognized by ÉCRANS (the top bar,
// the calendar) and the router’s GARDES (features that are not
// widgets). It is stored in a single object, a ChangeNotifier:
//    - a private field, the state;

import 'package:flutter/foundation.dart';

enum Role { admin, doctor, user }

typedef Utilisateur = ({String login, Role role});

// three "hard-coded" accounts (password = login)
const _comptes = {'admin': Role.admin, 'pelissier': Role.doctor, 'martin': Role.user};

class Session extends ChangeNotifier {
  Utilisateur? _utilisateur; // status: null, no one is logged in

  Utilisateur? get utilisateur => _utilisateur;

  bool connecter(String login, String password) {
    final role = _comptes[login];
    if (role == null || password != login) {
      return false;
    }
    _utilisateur = (login: login, role: role);
    notifyListeners();
    return true;
  }

  void deconnecter() {
    _utilisateur = null;
    notifyListeners();
  }
}

    // =========================================================================
// lib/ex18_gardes/routes.dart - PROTÉGÉES routes protected by guards
// -------------------------------------------------------------------------
// redirect: a function that go_router calls AVANT on every navigation
// (that of GoRouter: for all routes; that of a GoRoute:
// for that route alone). It receives the navigation status (state.uri:
// the requested address) and returns:
//    - null: navigation continues;
//    - an address: navigation is replaced by navigation to
//      that address.
// refreshListenable: an object at ÉCOUTER; when it signals a
// change (session: login, logout), the router reevaluates
// its guards for the current screen.
//
// This is the client-side equivalent of the guards NestJS (JwtAuthGuard,
// RolesGuard) — with one difference, FONDAMENTALE: a client guard is
// merely a convenience. The application is in the hands of the user, who
// can modify it at will. True data protection remains that
// provided by the SERVEUR (see the chapter on the black box).
// =========================================================================

import 'package:go_router/go_router.dart';

import 'coquille.dart';
import 'pages/accueil.dart';
import 'pages/administration.dart' deferred as administration;
import 'pages/agenda.dart';
import 'pages/connexion.dart';
import '../ex17_routeur/pages/chargement_differe.dart';
import 'session.dart';

// the “login required” prompt: not logged in -> to the login page,
// remembering where you wanted to go
String? connexionRequise(GoRouterState state) {
  if (session.utilisateur == null) {
    return Uri(path: '/connexion', queryParameters: {'redirect': state.uri.toString()}).toString();
  }
  return null;
}

// the “role required” guard: a function that triggers FABRIQUE a guard
String? Function(GoRouterState) roleRequis(Set<Role> roles) {
  return (state) {
    final u = session.utilisateur;
    if (u == null || !roles.contains(u.role)) {
       // is logged in, but not with the correct role: returns to the home page, with a reason
      return Uri(path: '/', queryParameters: {'refus': state.uri.path}).toString();
    }
    return null;
  };
}

final routeur = GoRouter(
  refreshListenable: session,
  routes: [
    ShellRoute(
      builder: (context, state, child) => Coquille(child: child),
      routes: [
        GoRoute(
          path: '/',
          builder: (context, state) => Accueil(refus: state.uri.queryParameters['refus']),
        ),
        GoRoute(
          path: '/connexion',
          builder: (context, state) => Connexion(redirection: state.uri.queryParameters['redirect']),
        ),
        GoRoute(
          path: '/agenda',
          redirect: (context, state) => connexionRequise(state),
          builder: (context, state) => const Agenda(),
        ),
        GoRoute(
          path: '/administration',
           // the guards, in order: the first one that returns an address wins
          redirect: (context, state) => connexionRequise(state) ?? roleRequis({Role.admin})(state),
           // the page code is loaded only after the guards have been passed
          builder: (context, state) =>
              ChargementDiffere(charger: administration.loadLibrary, construire: () => administration.Administration()),
        ),
      ],
    ),
  ],
   // any other address (no matching route): return to the home page
  onException: (context, state, routeur) => routeur.go('/'),
);

    With [go_router], a guard is a redirect function, called before each navigation (the one for [GoRouter]: for all routes; the one for [GoRoute]: for that route alone). It receives the navigation state and returns:

    • [null]: the navigation continues;
    • an address: the navigation is replaced by a navigation to that address.

    The code:

    • lines 34–38: the “connection required” guard: not connected? Redirects to the login page, while retaining the intended destination (parameter [redirect]);
    • lines 42–47: the “role required” guard is generated by a function that receives the permitted roles and returns the guard. Logged in, but without the correct role: redirect to the home page, with a reason (parameter [refus]);
    • line 54: the router monitors the session: when it detects a change (login, logout), it reevaluates the guards for the current screen. If you log out from the calendar, you are immediately redirected to the login page;
    • line 69: the calendar requires the user to be logged in;
    • line 75: the administration page requires the user to be logged in (ET) and to have the role (ADMIN): the checks are chained with [??]; the first one that returns an address takes precedence;
    • Lines 77–78: The code for the administration page is loaded only after the guards have been passed;
    • line 84: any other address redirects to the home page.

    This is the client-side equivalent of the server checks [NestJS] ([JwtAuthGuard], [RolesGuard]), with one difference: FONDAMENTALE—a client-side guard is merely a convenience (to avoid displaying an unnecessary screen). The application is in the user’s hands, who can modify it as they wish; true data protection remains on the server, which re-verifies everything with every request (see the chapter on the black box).

import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

import '../session.dart';

class Connexion extends StatefulWidget {
  final String? redirection;

  const Connexion({super.key, this.redirection});

  @override
  State<Connexion> createState() => _ConnexionState();
}

class _ConnexionState extends State<Connexion> {
  final _login = TextEditingController();
  final _password = TextEditingController();
  bool _erreur = false;

  @override
  void dispose() {
    _login.dispose();
    _password.dispose();
    super.dispose();
  }

  void _valider() {
    if (!session.connecter(_login.text.trim(), _password.text)) {
      setState(() => _erreur = true);
      return;
    }
     // Only a path like INTERNE is accepted: it starts with /, but not with //
     // (//site.com/... refers to a AUTRE site) - no redirection to another site
    final r = widget.redirection;
    final interne = r != null && r.startsWith('/') && !r.startsWith('//');
    context.go(interne ? r : '/');
  }

  @override
  Widget build(BuildContext context) {
    return ListView(
      children: [
        if (widget.redirection != null)
          Card(
            color: Colors.amber.shade50,
            child: Padding(
              padding: const EdgeInsets.all(12),
              child: Text('Connectez-vous pour ouvrir ${widget.redirection}.'),
            ),
          ),
        TextField(
          controller: _login,
          decoration: const InputDecoration(labelText: 'login'),
        ),
        TextField(
          controller: _password,
          obscureText: true,
          decoration: const InputDecoration(labelText: 'mot de passe'),
          onSubmitted: (_) => _valider(),
        ),
        const SizedBox(height: 16),
        Align(
          alignment: Alignment.centerLeft,
          child: FilledButton(onPressed: _valider, child: const Text('Se connecter')),
        ),
        if (_erreur)
          const Padding(
            padding: EdgeInsets.only(top: 8),
            child: Text('Login ou mot de passe incorrect.', style: TextStyle(color: Colors.red)),
          ),
      ],
    );
  }
}
    • lines 41–43: After login, the user is redirected to the page they wanted to open (parameter [redirect] set by the guard), or to the home page. Only an internal path is accepted: it begins with [/], but not with [//] ([//site.com/...] refers to a AUTRE site). On the web, a login URL generated by a third party ([/connexion?redirect=//site-pirate.com]) will therefore never lead anywhere else.
